# TRUST404 Track 04 Compatibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make QProver a valid official TRUST404 Track 04 autonomous exploit-prover submission while preserving the existing core.

**Architecture:** Add a `qprover.trust404` adapter that maps official inputs to a deterministic QProver `SearchProblem`; execute candidates through the official Foundry harness; package the standard CLI and required submission files around the unchanged core.

**Tech Stack:** Python 3.12+, existing QProver search/QUBO modules, Foundry, Solidity 0.8.24, organizer Harness.sol.

**Spec:** `docs/superpowers/specs/2026-09-15-trust404-compat-design.md`

## Global Constraints

- Official manifest schema accepted: `trust404.track04.manifest/0.1` only.
- Official CLI flags and exit codes are exact.
- No target-name/label/witness hardcoding in production candidate selection.
- Network-independent runtime; LLM is not required.
- Official harness is the final proof oracle.
- Same seed and inputs must produce the same candidate ordering and output.
